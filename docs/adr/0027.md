# 0027 工作台、练习、回测的价格统一只按拆股复权

- 状态：采纳（随 PR 合并生效；不合并就改写成"不做"）
- 日期：2026-11-21

## 背景
同一个工作台里有两种价格口径：

- 只按拆股复权：Polygon `/v2/aggs?adjusted=true`（实测 QQQ 2025-06-02 收盘 523.21，等于 yfinance 不按分红复权的 523.21；按分红复权是 519.58），以及回测出信号用的价格（`evaluate.py`、`plansim.py`、`fullplan.py` 用 yfinance `auto_adjust=False` 的开高低收）。
- 拆股、分红都复权：`dma_analyze.py` 和 `hourly.py` 的 yfinance 回退，以及 `backtest.py --fetch-only`（练习题库的 `data/practice/prices/`、`app/scripts/replay.ts` 都经它取数），用的是 `auto_adjust=True`。

Polygon 套餐只覆盖近几年。回放更早的日子会 403，回退到 yfinance。QQQ 2014-03-28 的收盘因此显示 79.18，回测和真实收盘是 87.05。卡片上的进场价、止损、目标和回测下的单差了约一成，对不上。

## 决定
所有取数路径都只按拆股复权，不按分红调：

- `dma_analyze.fetch_yfinance`、`hourly.fetch_yfinance_1h` 改用 `auto_adjust=False`，只留开高低收量，不用 Adj Close。数据来源写成"Polygon/Massive（日线，只按拆股复权）""yfinance（日线，只按拆股复权）"。
- `backtest.ensure_data`（`--fetch-only`）改用 `auto_adjust=False`，缓存存开高低收量加 Adj Close，和 `evaluate.py` 的 `data/eval/` 一个格式。有没有 Adj Close 列就是口径标记：改之前的缓存没有这一列，下次取数时自动重取覆盖，不用手动删。
- 收益口径不变：`fullplan.py`、`evaluate.py` 照旧用 Adj Close 算含分红的收益。旧的 `backtest.py` 逐笔回测本来用收盘价算收益，改完以后收益不含分红，报告里写明。

## 理由和出处
- 脚本自定。Polygon 的 `adjusted=true` 只按拆股复权，没有含分红的选项，工作台的主数据源只能是这个口径；回测出信号早就是这个口径。让回退跟着主数据源走，改动最小，也不用重跑回测。
- 含分红复权的历史价每次分红都会整体下移，同一天的卡片过一个季度再回放，价位就变了。只按拆股复权的价格只在拆股时变，变了也是整体按比例，均线方向和相对关系不变。
- 实测：QQQ 2014-03-28 用 yfinance `auto_adjust=False` 收盘 87.05，`auto_adjust=True` 是 79.18（`tests/test_price_basis.py` 最后一条，联网时跑）。

## 影响
- 工作台回放 Polygon 覆盖不到的日子（以及选了 yfinance 数据源时），价位和回测一致。小时线回退只有最近约 730 天，分红差得少，口径也一并统一。
- 练习：新开的题用拆股复权价换算成指数。已经开过的题有自己的 CSV（`data/practice/<id>.csv`），不重算；识别题库里已经生成的题也不重算。`data/practice/prices/` 和 `reports/replay/data/<票>.csv` 下次取数时重取。
- `references/backtest-record.json`（旧逐笔回测的记录，结论卡片引用）没有重跑，还是旧口径；下次重跑 `backtest.py` 才换（已换，见后续）。
- `fullplan.py` 不受影响：它的行情是 `data/eval/`，本来就是这个口径。`test_planrun` 逐笔对照不变。

## 什么情况下重新考虑
- Polygon 套餐换成覆盖全部历史：回退路径很少用到，口径仍按这条。
- 要在旧的 `backtest.py` 里算含分红收益：照 `evaluate.load_prices` 用缓存里的 Adj Close，不改出信号的价格。
- yfinance 改了 `auto_adjust` 的默认值或返回的列：`tests/test_price_basis.py` 会先失败。

- 新记录的每日决定点里去掉"只因 P24 让位"：稳定上涨 34、回撤 27、横盘 2 笔，回到旧记录的量级。
