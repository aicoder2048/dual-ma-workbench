# 0029 找打法按做决定的顺序排成固定的格子，技术细节挂在格子下面当依据

- 状态：采纳（随 PR 合并生效；不合并就改写成"不做"）
- 日期：2026-11-21

## 背景
用户 2026-11-21 说中栏「找打法」"写的有点多而乱，没有章法和结构"。原来的顺序是：打法一句、脚本原话一段、还差什么、整张条件清单，然后是计划的条目一条条往下排（等什么、怎么进、触发价推演、目标、到目标、盈亏比、股数、筹码山参考、进场后止损、失效……）。每套打法条目不一样，空仓不买的打法没有止损、目标、股数，条目直接少掉，看不出缺的是哪一块；筹码山、推演求解这种辅助信息和主条件排在一起。

## 决定
只改显示，不动计算和回测。

1. 计划排成固定的格子，空仓、持仓还是用原来的切换（切换也决定图上画哪组价位线）。
   - 空仓六格：① 能不能做 → ② 等什么信号 → ③ 进场价 → ④ 止损 → ⑤ 目标和盈亏比 → ⑥ 仓位。
   - 持仓五格：① 拿着还是走 → ② 盯什么信号 → ③ 止损 / 离场价 → ④ 目标 → ⑤ 浮盈 / 浮亏怎么办。
2. 条目归哪一格只看一张表（`public/viz.js` 的 `CELLS`，按 `plan.ts` 条目的 label）：每格分正文和依据。表里没有的 label 直接报错；单元测试把九套打法 × 四种处境都过一遍，每一条只出现在一格里、每一格都有内容。
3. 技术细节不再单独成条，挂在它支撑的那一格下面，默认折叠（「依据 · 条件清单」这样写出里面有什么）：条件清单（含构造、2B 等规则的状态）在 ② 下面，触发价的推演求解在 ③，横盘的"避不开死叉就提前走"和财报提醒在止损，筹码山参考带在目标。规则编号按钮跟着条目走。脚本原话也折叠起来。
4. 一格没有内容时写"—"和为什么（例如"— 不进场，不算股数"、持仓目标写脚本给的"下跌趋势还没拐头向上，持仓不找目标位……"），格子不消失。
5. 第一格开头一个词：空仓是做 / 等 / 不做，持仓是拿着 / 减仓 / 离场，配颜色，后面是原来的做法那句。做法本来就以这个词开头时不写两遍。

数据字段：
- `Plan` 加 `verdict`（上面那个词）。空仓按交易计划判：没有进场、或盈亏比不到 3:1（触发价离现价还远时不算）是不做；进场条件今天就齐了（P2、P21、P14）是做；其余是等。持仓按打法查表（`HOLD_VERDICT`）。进场规则的价位标签和"今天齐没齐"并成一张表 `ENTRY`。
- 空头结构反弹中空仓那条 J17 推演的 label 从"推演"改成"等多久"：原来和横盘止损的推演同名，归不进同一格。长风读的 `planLine`、`planFacts`（`结论.*`、`计划.*`）不读 label，不变；交易日志存的条目照旧。

## 理由和出处
- 顺序照交易者下单前的问题：能不能做、等什么、在哪进、错了在哪走、能赚多少值不值、买多少。持仓换成拿不拿、盯什么、在哪走、看到哪、浮盈亏怎么办。
- 格子固定，空着的地方写为什么，读的人一眼知道"这套打法本来就没有止损"，不是漏了。
- 归属用一张表，不散在各打法里写 if：加一条新条目时要么进表，要么测试先失败。

## 影响
- 找打法比原来短：依据默认收起，点开才看条件清单、推演、筹码山。e2e 里看条件清单、筹码山、推演的用例都改成先点开依据。
- 结论卡片、Markdown 报告、长风的数据字段不受影响。

## 什么情况下重新考虑
- 用户觉得要点开才看得到条件清单不方便：把 ② 的依据默认展开。
- 空仓、持仓想同时看：两列（宽屏）或上下两段，格子不变。
