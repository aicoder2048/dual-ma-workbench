# 0038 看大局第 ④ 问加阶段决策树、过渡状态写明原因；分析输出加 crossed、why 两个字段

- 状态：采纳
- 日期：2026-11-22

## 背景
- 写双均线概念图解时，要把每个说法对照代码画成图（PR #86、#87）。图解里的阶段决策树、过渡状态示意，比工作台第 ④ 问的一句话清楚。
- 对照时还发现一个错误（随这次一起修）：稳定上涨 / 下跌里 20/60 已交叉时，`regime._stage` 仍给「回撤中 / 反弹中」（J7，深回撤 / 深反弹），第 ④ 问却固定写「但还没交叉，算回撤，不算转折」，后面又说「交叉了算转折」，和类型标签互相矛盾。
- 过渡状态时，第 ④ 问只写「类型没定，阶段按过渡状态看」，看不出是哪一种、为什么。顶部 / 底部转折中有两种情况（60 先转向；或 60 已跟着走、只差 120 拐过来），失序是兜底，读的人不知道哪条对不上。

## 决定
只改显示，加两个输出字段，不动判定、计划和回测。

1. `regime` 多两个字段：
   - `crossed`：20/60 已交叉或 20 已到 60 另一边（和 `_stage` 共用 `_crossed`）。前端据此写深回撤 / 深反弹，不另推一套。
   - `why`：过渡状态为什么叫这个名字（`transition_why`，照 `classify` 的 order、dir60、dir120 分支写）；有类型时为空。
2. 第 ④ 问：
   - 按是否已交叉分开写；规则句改成「破线、拐头算回撤；交叉以后，稳定类型仍叫回撤（深回撤），加速类型才叫转折（J7、J15）」。
   - 有阶段时画三问决策树（20 线组走出反向一步了吗 → 20/60 交叉了吗 → 稳定还是加速），高亮当天走的那条路，和概念图解「五种趋势类型」页同一套问法。横盘、过渡状态没有阶段，不画。
   - 过渡状态写「「名字」：原因」，再说一句打法按过渡状态给（J6）。
3. 顶上「趋势类型」小格在深回撤 / 深反弹时加一个小标。

## 理由
- 图解证明决策树比文字好懂；放在第 ④ 问里，读者看到的是自己这只票走的那条路，不只是一般规则。
- 原因用字段带出来，前端只负责显示：判定逻辑只在 `regime.py` 一处，免得前端和脚本各写一套、以后改一边漏一边。
- 名字是脚本自定的（J6），写出原因比改名字更有用：名字难懂是因为它本来就是兜底分类。

## 影响
- 分析 JSON 的 `regime` 多 `crossed`、`why`；旧的分析文件没有这两个字段，前端按"没交叉、没原因"处理。
- `regime.py` 改了，`fullplan` 的每日缓存指纹会变，下次在主检出跑完整计划回测要重算（约 50 分钟），计划本身不变。

## 什么情况下重新考虑
- 用户觉得决策树占地方：默认折叠，或只在过渡 / 深回撤时显示。
- 以后要把过渡状态的原因也放进结论卡片或找打法。
