# 0020 K 线着色的来源可插拔，私有着色规则不进仓库；练习只用自带规则

- 状态：采纳
- 日期：2026-11-20

## 背景
工作台按破线拐头信号给 K 线上色。自带的着色规则是 LEI 黑绿线指标第一个因子的简化版，只看 MA20 的破线和拐头，图例里一直写明它不是他的黑绿线。LEI 没有公开他的指标代码。用户可以在自己的机器上用一套更接近的私有规则，但这个仓库是公开的。

## 决定
颜色怎么算做成可插拔。仓库里只有接口和自带规则（`tones.py`）。本机配了着色插件就用插件的颜色，没配就和以前一样。

私有着色规则不进仓库。`private/` 在 `.gitignore` 里。仓库里的代码、文档、测试和提交信息只谈接口，不描述任何私有规则的内容。测试里的假插件用一眼看得出是假的规则（按日期单双上色）。

练习只用自带规则，不读插件。盲测回放和识别题都是。网页报告（`dma_analyze.py --html`）也只用自带规则。

回测和规则不读颜色，保持不读。

不做多个插件并存、热加载、设置面板里的开关。

## 理由和出处
- 用户决定（2026-11-20）。
- 练习的题目和答案要在每台机器上一样。读了插件，同一道题在两台机器上的图就不一样。
- 网页报告可能发布出去。读了插件，插件的名字和图例说明会写进报告文件。
- 着色只是图上的提示。它不进规则，评估和回测的数字和它无关。

## 影响
- 插件是一个 Python 文件，暴露 `NAME`、`LEGEND` 和 `tones(df)`。约定和查找顺序写在 `tones.py` 的文档字符串里：先看环境变量 `DMA_TONE_PLUGIN`，再看仓库根目录 `.env` 里的同名一行，最后看 `private/tone_plugin.py`。空值表示不用插件。
- 图表数据多一个字段 `tone_source`（`key`、`name`、`legend`、`warning`），日线和周线各一份。「图层」菜单里「着色」那一行读它（2026-11-21 接上）：写 `name` 和 `legend` 的第一行，整段 `legend` 在悬停的说明和「?」面板里，切换日线、周线跟着换。自带规则的说明只在 `tones.BUILTIN` 里有一份，前端不再留。旧的分析结果没有 `tone_source`，菜单里写一行兜底说明。
- 插件出错时退回自带规则，原因写在 `tone_source.warning` 里，同时打到 stderr。分析不会因为着色插件失败。网页上，这句原因直接显示在「图层」菜单里「着色」那一行下面，「?」面板里也有。
- 练习走 `dma_analyze.py --builtin-tones`，识别题的 `scan.py` 固定只用自带规则。
- 分析结果缓存在服务端内存里。换了插件或改了 `DMA_TONE_PLUGIN`，要重启服务才生效。
- `tones.py` 和 `html_report.py` 一样，不进完整计划缓存、逐笔回测缓存的指纹，也不进验证集的冻结哈希。

## 什么情况下重新考虑
LEI 公开了黑绿线指标的代码或完整规则，并且入库核过原话：这时自带规则可以直接照他的写。或者要同时比较几套着色规则，一个插件不够用。
